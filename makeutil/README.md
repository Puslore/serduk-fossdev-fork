# Автоматизация рабочего процесса Python-проекта с использованием GNU Make

Данный проект представляет собой реализацию системы автоматизации с помощью Makeutil для Python-разработки. Основная цель — обеспечить **воспроизводимость**, **изоляцию** и **автоматическую проверку качества кода** без необходимости ручной настройки окружения пользователем.

---

## Философия проекта
*   Система **автоматизированна**, способна собирать проект, входить в виртуальное окружение, обнаруживать недостающие импорты в коде, вносить их в файл зависимостей и устанавливать, запускать тесты.

## Структура проекта
```text
makeutil/
├── src/                # Исходный код приложения
│   ├── app.py          # Точка входа
│   └── calc.py         # Модуль с логикой сложения чисел
│   └── example.py      # Модуль, демонстирующий работу автопроверки стилей
│   └── service.py      # Модуль, демонстрирующий работу автопроверки недостающих библиотек
├── tests/              # Юнит-тесты (pytest)
│   ├── test_calc.py    
│   └── test_foo.py
├── .venv/              # Изолированное окружение (создается автоматически)
├── Makefile            # Главный сценарий автоматизации
└── requirements.txt    # Список внешних зависимостей
```

### До внедрения Makefile (Ручной режим):
1. Проверить наличие Python 3 в системе.
2. Создать виртуальное окружение: python3 -m venv .venv.
3. Активировать его: source .venv/bin/activate.
4. Обновить pip и установить зависимости: pip install -r requirements.txt.
5. Проверить код на ошибки типов: mypy src.
6. Запустить линтер: flake8 src.
7. Запустить тесты: pytest tests.
8. При нахождении ModuleNotFoundError вручную искать имя пакета и добавлять в requirements.txt.
9. Установить недостающие зависимости.

### Автоматизация (Make):
Достаточно запустить проект:
`make run`
Войти в виртуальное окружение:
`make shell`
Запустить проверки:
`make check`

## Описание таргетов Makefile

| Таргет | Описание |
| :--- | :--- |
| run | Сборка приложения, создание виртуального окружения|
| shell | Вход в интерактивную оболочку с настроенным путем к .venv/bin. Выход из него осуществляется командой `exit`. Решена проблема statable состояния терминала.|
| clean | Полное удаление виртуального окружения и временных файлов. |
| check-requirements | Анализирует import в src/, сравнивает с установленными пакетами, обновляет requirements.txt и доустанавливает недостающее. |
| test | Запуск юнит-тестов pytest с поддержкой параметризации. |
| typecheck | Статический анализ типов с помощью mypy. |
| lint | Проверка стиля кода по PEP8 с помощью flake8. |
| format | Автоматическое форматирование кода инструментом black. |


## Реализованные механизмы

### 1. Изоляция окружения
Makefile автоматически отслеживает изменения в requirements.txt. Если файл изменен или папка .venv отсутствует, таргет `$(VENV)/bin/activate` инициирует пересборку окружения. Все инструменты (PYTHON, PIP, MYPY) вызываются по абсолютным путям.

### 2. Автоматическое управление зависимостями
Таргет check-requirements реализован как Bash-скрипт внутри Makefile. Он:
* Использует grep и sed для поиска всех импортов.
* Пытается выполнить import <module> внутри venv.
* При неудаче — дописывает модуль в requirements.txt и запускает pip install.

### 3. Гарантия качества 
Интеграция mypy и pytest позволяет отлавливать ошибки на этапе сборки. Благодаря зависимостям между таргетами в Makefile, тесты не будут запущены, если код не прошел проверку типов, что экономит время разработчика.

---

### Инструкция по запуску:
1. Клонировать репозиторий.
2. Перейти в папку makeutil.
3. Запустить `make run`, `make shell` и `make check` — система сама создаст окружение и проверит проект.
